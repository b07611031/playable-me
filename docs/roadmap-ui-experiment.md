# Playable Me — 後續開發計畫、UI 技能候選與比較基準

更新：2026-10-31

## 已確認方向

- 使用情境：求職與專業交流，QR Code 掃描後 60–90 秒內能認識 Yun。
- 視覺：復古像素 RPG；模式 A（輕量點擊探索、不做角色搖桿移動）。
- 希望留下的印象：快速學習能力、AI 工程背景、對遊戲的熱忱。
- 目前 MVP：基本資訊與三條故事路線已可傳達；使用者已驗證「作為初始版本達到提供資訊功能」。
- 優先順序：**先增加遊戲互動 → 再優化 UI → 最後做前後比較**。目前不應提早整體改版 UI。
- 新增正式專業連結：LinkedIn https://www.linkedin.com/in/yunlin-ntu/ 。

## Phase 1：豐富遊戲互動（優先）

目標：從「點擊故事清單」轉成「發現場景物件、短互動，透過遊戲了解 Yun」，仍適合手機、快速略過、可隨時開 LinkedIn。

依優先順序評估：
1. 場景直接點擊物件，hover / tap 提示、角色視線或短反應，取代純卡片式探索；每區 2–3 個互動點。
2. 輕量支線／彩蛋：Game Room 舊電腦 → 太空船遊戲微型互動（約 10–20 秒，可略過）；Quest Field → 以簡短選擇呈現練習與回饋；AI Lab → 輕量的「問題 → 驗證 → 迭代」決策。
3. 互動成功音效（預設靜音或可關閉）、像素粒子、物件／人物 2–3 幀微動畫；尊重 prefers-reduced-motion。
4. 發現、閱讀完成與成就解鎖分開計數；不應只是「點開第一頁」就解鎖。
5. 可隨時跳過所有遊戲、閱讀完整內容，且「3 個成就」不是查看履歷／LinkedIn 的門檻。

**避免**：戰鬥系統、繁複背包、長動畫、冗長問答、必須過關才能拿到履歷；避免把面試官當成玩家強制教學。

## Phase 3：前後比較的實驗設計

比較至少三個版本（避免混淆「增加遊戲性」與「視覺改善」）：
- **A**：v0.1 初始 UI + 初始互動。
- **B**：加入遊戲互動，但尚未應用 UI Skills 的版本。
- **C**：在 B 基礎上，完成 UI audit 和 UI 優化的版本。

受控條件：相同故事資料、語言、裝置與 viewport、瀏覽器、內容情境；每個版本均採相同測試腳本。

比較方式：
- 視覺：首頁、世界地圖、各區、故事對話框、成就、聯絡頁；桌面 1440×900 與手機 390×844 截圖前後並排。
- 可用性：首次進入是否能在 10 秒找到 Resume / LinkedIn、首次點擊互動物件是否易理解、完成三路線所需時間；記錄卡住與跳出的位置。
- 敘事與求職目標：60–90 秒體驗後，能否無提示說出 **Fast Learner / AI Builder / Passionate Gamer**。
- 技術：建置通過、無 JS runtime error、鍵盤／觸控、對比度、字級、減少動態、效能和動畫流暢程度。
- 可用 3–5 位試用者蒐集定性回饋；小樣本不能當成統計顯著改善。
- 為區分改善來源，B→C 只能改 UI／動效，不改主要玩法與內容；重大內容修正需另記錄。
- 產出 `docs/ui-before-after.md`：截圖連結、同場景 A/B/C、發現問題、改動、測試結果、仍待改善項目。

## 建議後續分支與驗收

- `feat/game-interactions`：先加場景可點擊熱區和一個微型互動，測試後擴充。
- `feat/ui-polish`：完成 B 的功能並凍結後才開展；每個視覺調整追溯到 audit 指出問題。
- 禁止直接覆蓋對照基準；不要僅因新 UI 新鮮感就斷言更有效。
